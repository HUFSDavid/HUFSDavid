# David 독해 해설강의 PPT

학생들이 **숙제로 먼저 풀어 온** 독해 Exercise 세트를 수업 시간에 한 문제씩 해설하는 PPT를 만든다.
사용자는 설명에 자신 없는 초보 선생님일 수 있다. 그래서 슬라이드는 학생이 보는 화면답게 깔끔하게 만들고, 선생님이 할 말은 전부 **발표자 노트**에 대본으로 넣는다.

디자인과 레이아웃은 `scripts/build_deck.js`가 고정으로 처리한다. 이 스킬에서 할 일은 **내용(JSON)을 정확하고 친절하게 채우는 것**이다.

## 덱 구성 (이 순서가 사용자와 확정한 형식)

1. 표지
2. **채점: 정답 한눈에 보기**: 숙제를 채점하고 시작하므로 맨 앞에 둔다. 함의 문제 카드는 붉은색으로 구분된다.
3. 수업 순서
4. 풀이 공식: 3단계, 신호어 4종, 오답 함정 4종, 함의 추론(세트에 함의 문제가 있을 때만)
5. Part 구분 슬라이드: 6문제씩 1차시
6. 문제마다 5장
   - **지문 + 보기**: 발문, 원문 전체, 각주, ①~⑤를 시험지처럼 보여 준다. 형광이나 해석은 넣지 않는다.
   - **정답 근거 & 문법 포인트**: 문장 번호를 붙이고, 정답 근거 문장은 노란 형광, 문법·내신 포인트는 **파란 굵은 글씨로만** 표시한다(ⓐⓑ 같은 기호 없음).
   - **문법·내신 포인트**: 구절, 문법 이름, 짧은 설명을 행으로 정리한다.
   - **흐름 잡기**: 빈칸(밑줄) 문장, 찾을 것, 글의 흐름 4단계, 결정적 단서.
   - **정답 & 오답 체크**: 선택지마다 이유와 함정 라벨(정답/반대/언급 없음/소재 함정/범위 오류)을 단다.
7. 마무리: 핵심 공식과 복습 과제

"단어 포함" 요청 시: 근거 슬라이드 지문의 어려운 단어에 초록 점선, 뜻은 **슬라이드 하단 어휘 박스**에 넣는다 (단어 옆 괄호 주석은 사용자가 거절함).

사용자가 이미 거절한 것: **슬라이드 위의 한글 해석**("교사용 퀄리티"라 학생 화면에 맞지 않음), 문법 포인트의 ⓐⓑⓒ 기호.
문장별 해석은 '정답 근거' 슬라이드의 발표자 노트로 자동으로 들어간다.

## 작업 순서

### 1. 원문 추출
- docx는 `pandoc input.docx -t plain`, PDF는 pdf 스킬, 사진은 직접 읽는다.
- 지문은 **철자·구두점까지 원문 그대로** 옮긴다. 학생이 숙제로 본 것과 화면이 같아야 하기 때문이다.
- 다만 선택지 안의 명백한 오타(예: previals → prevails)는 고친다. 고친 내용과 지문·각주 오류(다른 지문 각주가 섞인 경우 등)는 노트와 최종 보고에 적는다.

### 2. 문제 풀기 (가장 중요)
- 모든 문제를 직접 풀고, 정답 근거 문장을 지문에서 찾아 확정한다. 정답이 틀리면 수업 전체가 무너진다.
- 애매하면 선택지 다섯 개를 모두 빈칸에 대입해 보고, 오답 이유가 각각 분명한지 확인한다.

### 3. 데이터 JSON 작성
- 필드 설명과 작성 기준은 `references/data_schema.md`를 읽고 따른다.
- 요약문·삽입·어휘 유형이나 "단어 포함" 요청이면 `assets/example_unit08_summary.json`(요약문 10 + 변형 3, 어휘 박스)을 기준으로 삼는다. `summary`/`given`/`vocab` 등 선택 필드는 data_schema.md 참고.
- `assets/example_suteuk03.json`은 사용자가 만족한 완성본(수능특강 03강, 빈칸 10 + 함의 2)이다. 톤, 분량, 노트 대본 스타일은 이 파일을 기준으로 맞춘다.
- 세트 구성이 달라지면(문제 수, 유형) `intro`의 3단계·신호어·오답 함정 예시를 **이번 세트의 실제 문제 번호**로 다시 쓴다.

### 4. 빌드
```bash
WORK=<scratchpad>/reading-ppt && mkdir -p $WORK && cd $WORK
[ -d node_modules/pptxgenjs ] || (npm init -y >/dev/null && npm install pptxgenjs react react-dom react-icons sharp >/dev/null)
NODE_PATH=$WORK/node_modules node <skill-dir>/scripts/build_deck.js data.json "<출력 경로>/<교재>_<강>_수업PPT.pptx"
```
- 파일명 예: `수능특강_영어_03강_수업PPT.pptx`

### 5. 검수
- pptx 스킬의 `scripts/office/validate.py`로 파일을 검증한다.
- soffice로 PDF→이미지 변환해 확인한다. 특히 다음을 본다.
  - **지문+보기** 슬라이드에서 ⑤번이 상자 밖으로 넘치지 않는지. 넘치면 그 문제에 `"qFont": 13.5`처럼 글자 크기를 직접 지정한다.
  - 문법 구절이 파란색으로 표시됐는지. 구절이 지문에 **정확히 한 번** 나오는 부분 문자열이어야 표시된다.
  - 정답 근거 형광이 의도한 문장에 들어갔는지.
- 문법 구절 검사는 다음 한 줄로 한다.
  ```bash
  node -e 'const D=require("./data.json");for(const e of D.exercises){const t=e.sentences.map(s=>s[0]).join(" ");for(const g of e.grammar||[])for(const p of g[0]){const c=t.split(p).length-1;if(c!==1)console.log(e.n,p,c)}}'
  ```

### 6. 전달
- 파일을 보내고, 채팅에는 짧게 정리한다.
  - 정답 목록
  - 교재 오류·수정 사항
  - 시간 배분(문제당 약 8~9분이라 6문제 = 1차시)
  - 사용자가 확인할 것(지문이 긴 문제의 글자 크기, 문법 포인트 선택이 학교 출제 경향과 맞는지)
- 사용자가 "빠르게 수업 준비하는 법"을 물으면 이렇게 안내한다.
  1. 채점 슬라이드로 정답 숙지
  2. 발표자 노트 읽기
  3. 교재에 근거 문장 밑줄
  4. 풀이 공식 슬라이드 리허설

## 내용 작성 원칙 (왜 이렇게 하는지)

- **노트는 대본처럼 쓴다.** 【도입 질문】, 【풀이 핵심】, 【오답 설명】, 【어휘】 같은 머리표를 쓰고, 선생님이 그대로 읽을 수 있는 말투("~해 볼까요?")로 쓴다. 초보 선생님이 노트만 보고도 수업할 수 있어야 한다.
- **정답 근거 문장(형광)은 지문당 2~4개.** 빈칸 내용을 재진술하거나 예시들의 공통점을 보여 주는 문장만 고른다. 너무 많이 칠하면 강조가 사라진다.
- **문법·내신 포인트는 지문당 4~5개.** 내신 어법에 실제로 나오는 것(수일치, 병렬, 관계사, 분사구문, 도치, 강조구문, 공통관계, 5형식 보어, 사역동사, 가정법) 위주로 고른다. 설명은 "왜 이 형태인지"를 한 줄로 쓴다.
- **오답 이유는 지문에 근거해서 쓴다.** 그리고 함정 라벨 네 가지 중 하나를 붙인다. 학생이 "이건 어떤 함정?"을 맞히는 활동에 쓰이기 때문이다.
- **흐름 4단계**는 글의 구조(주장 → 근거/예시 → 결론 등)를 한 줄씩 한국어로 쓴다. 마지막 단계가 빈칸과 연결되도록 쓴다.
