# 독해수업PPT (David 독해 해설강의 PPT)

학생들이 **숙제로 먼저 풀어 온** 독해 Exercise 세트를 수업 시간에 한 문제씩 해설하는 PPT를 만든다.
사용자는 설명에 자신 없는 초보 선생님이다. 슬라이드는 학생이 보는 화면답게 깔끔하게 두고, 선생님이 알아야 할 것과 할 말은 전부 **발표자 노트**에 넣는다.

디자인·레이아웃·애니메이션은 `scripts/build_deck.js`가 고정으로 처리한다. 이 스킬에서 할 일은 **내용(JSON)을 정확하고 친절하게 채우는 것**이다.

## 덱 구성 (사용자와 확정한 순서)

1. 표지
2. **채점: 정답 한눈에 보기**: 숙제 채점부터 하므로 맨 앞.
3. **수업 Objective** (`meta.objectives`: [목표, 부연] 3개).
4. 풀이 공식 3단계 (`intro.steps`)
5. **Signal 한눈에 보기 (타일 1장)** (`intro.signalMap`, 강성태 속독맵 10 UNIT)
   - 5×2 타일. 타일마다 UNIT 칩 + 구조 이름(`name`) + 단계(↓)별 대표 signal(`key`) + 오늘 지문 번호.
   - 사용자는 표보다 타일을 선호한다.
   - **지문마다 구조는 딱 하나**(`exercises[].unit`, `pre[].unit`). 여러 구조에 같은 지문을 중복 배정하지 않는다.
   - 오늘 지문 번호는 `unit` 값으로 자동 생성되고, 안 나온 구조는 회색 타일.
   - 자세한 signal 목록·독해 전략은 노트로.
6. 함의 추론 (함의 문제가 있을 때만), **기출 해체 등 교재 앞 문제**(`pre`, 클릭하면 정답)
7. Part 구분 (최대 7문제씩 1차시)
8. 문제마다
   - **Hook**: '생각해 볼까?' 질문 한 장 (활동 안내 문구 없이 질문만).
   - **어법 워밍업**: 그 지문의 파란 형광 문법 포인트(`grammar`)를 그대로 [A / B] 문제로 (`gq`, 포인트 수 = 문항 수, 최대 5). 클릭하면 정답.
   - **정답 근거 지문 (해설 메인)**
     - 제목은 얇은 한 줄. 본문 상자를 최대한 크게 쓰고, 글자 크기는 줄바꿈 계산으로 자동으로 최대치.
     - 노란 형광 = 정답 근거(`keyHL`, 단어·구 단위), 파란 형광 = 문법. 형광에는 **굵게 처리하지 않는다**.
     - 요약문: 얇은 **검정 테두리** 박스 (눈에 튀지 않게). (A)(B)만 빨간색.
     - 선택지 한 줄: **정답 선택지만 빨간 굵은 글씨** (체크 표시 없음). 선택지 없는 삽입·어휘형은 상자 오른쪽 아래 작은 '정답 ②'.
     - 지문 아래 **얇은 어휘 띠**: 단어·뜻 모두 검정, 굵게 하지 않음. 뜻은 클릭할 때마다 하나씩 나타난다 (학생에게 물어보며 채우기).
     - 노트 순서: 정답 → 풀이 플로우(`solve`, 정답을 모르는 상태에서 도출하는 과정) → 근거 이유(`keyWhy`) → 선택지 해설 → 하단 어휘 → 어휘·표현 확장 → 문법 → 수업 팁 → 문장별 해석.
   - **글의 구조 정리** (흐름 요약 대신 구조로 정리)
     - 위쪽: "글의 구조 UNIT 03 통념 – 반박".
     - 단계마다 `structure`: [역할, **지문 속 signal 원문**(연노랑 칩), 내용 한 줄].
     - 역할 이름은 속독맵 UNIT의 역할을 쓴다(통념·반박·연구 내용·연구 결과·결론 …). 필요하면 지문에 맞게 '재진술', '대조 정리'처럼 바꾼다.
     - 오른쪽: '꼭 가져갈 것'(`takeaways`) + **어휘·표현 확장**(`vocabPlus`).
       - 확장 기호: ≒ 유의어, ↔ 반의어, ⊕ 파생어.
       - 표현 바꿔쓰기도 넣는다. 예: regard A as B ≒ think of / look upon / see / view A as B, consider A (to be) B.
       - 사용자는 유의어·반의어·파생어를 중요하게 여긴다.
   - **교재 추가 문제 (`extras`)**: Plus Q·절대구문·절대어휘·절대어법 등 교재 문제는 **원문 그대로 전부** 싣는다 (학생이 숙제로 풀어 와서 채점함). 정답 박스는 클릭으로 공개.
9. **교재 Review Test** (`reviewTest`, 원문 그대로 + 클릭 정답)
10. **복습 미니테스트**: 어휘 스피드 퀴즈 + 어법 골든벨, 클릭하면 정답 (`review`).
11. 마무리: 핵심 공식과 복습 과제

## 독해 리뷰테스트 시험지 (Word, 함께 만든다)
수업 후 복습용 시험지. **15문항을 A4 한 장**에 담는다. 학생용 + 교사용(정답·해설) 2파일로 만든다.
- **표지**: David 공통 표지 v2(`scripts/coverlib.js`, 로고는 `assets/`)를 맨 앞 1쪽에 넣는다. 내지 머리글에는 DAVID 로고를 넣는다(david-cover 규칙).
- **구성 (기본 15문항)**
  - **A. 어휘 5**: 첫 글자를 주고 유의어(≒)·반의어(↔)·표현 바꿔쓰기를 쓰게 한다. 출처는 `vocabPlus`.
  - **B. 어법 5**: 지문 원문 문장에서 [A / B] 고르기. 출처는 파란 형광 문법 포인트(`grammar`).
  - **C. 글의 구조 2**: 지문 속 signal 발췌를 보고 <보기>에서 구조를 골라 쓰게 한다. 출처는 `structure`, `unit`.
  - **D. 요약문 5→3**: 요약문 (A)(B)를 첫 글자를 주고 쓰게 한다. 정답은 본문 정답 선택지의 단어.
  - 유형이 요약문이 아니면 D를 그 유형(빈칸 핵심어 쓰기 등)으로 바꾼다.
- 여러 지문에서 고르게 낸다. 문항마다 출처 (Ex N)를 단다.
- 교사용은 정답을 빨간색으로 넣고, 각 문항 아래 한 줄 해설을 붙인다.
- 데이터는 `reviewSheet`(data_schema.md)에 쓴다. 빌드 명령:
  `NODE_PATH=$WORK/node_modules node <skill-dir>/scripts/build_review_sheet.js data.json <출력 폴더>`
  → `<fileBase>_학생용.docx`, `<fileBase>_교사용.docx`
- 검수: PDF로 바꿔 각 파일이 **표지 1쪽 + 시험지 1쪽 = 2쪽**인지 확인한다. 넘치면 문항 문장을 줄인다.

### 사용자가 이미 거절한 것 (다시 넣지 말 것)
- **화면 구성**
  - 수업 순서 슬라이드 (→ Objective로 대체)
  - 별도 어휘 슬라이드 (→ 지문 아래 띠)
  - 시험지 원본 슬라이드 (→ 근거 지문 하나로 해설)
  - 정답&해설 슬라이드
  - 근거 찾기 미션 슬라이드
  - 문법 정리 전용 슬라이드 (→ 노트)
  - 오답 함정 라벨·함정 맞히기 슬라이드
  - Signal 카드 여러 장, Signal 표 (→ 타일 1장)
  - 흐름 정리의 내용 요약식 단계 (→ 글의 구조 + signal)
- **표시 방식**
  - 슬라이드 위 한글 해석 ("교사용 퀄리티")
  - 정답 근거 문장 통째 형광 (→ 단어·구 단위)
  - 슬라이드 위 근거 이유 박스·범례·"짝과 30초" 같은 활동 안내 문구
  - 지문 속 초록 어휘 표시
  - 문법 포인트의 ⓐⓑⓒ 기호와 파란 **글씨** (→ 파란 형광)
  - 형광 부분 굵게
  - 정답 뒤 ✔
  - 빨간 굵은 요약문 테두리
  - 초록·빨강 어휘 띠
  - 문법 포인트와 무관한 어법 워밍업
  - 한 지문에 여러 구조 배정

## 작업 순서

### 1. 원문 추출
- **교재 PPT·교재의 모든 문제를 빠짐없이 옮긴다**: 본문 문제, 기출 해체, Plus Q, 절대구문/어휘/어법, Review Test.
- 이미지로만 된 PPT는 슬라이드 이미지를 확대해 받아 적는다(서브에이전트로 병렬 처리). 정답은 해설서와 대조한다.
- 원본이 구글 드라이브에 있으면 드라이브에서 찾아 읽는다. 10MB가 넘어 받을 수 없으면 사용자에게 직접 업로드해 달라고 한다.
- 파일 형식별 읽는 법
  - docx: `pandoc input.docx -t plain`
  - PDF: pdf 스킬
  - 사진: 직접 읽는다
- 지문은 **철자·구두점까지 원문 그대로** 옮긴다. 학생이 숙제로 본 것과 화면이 같아야 하기 때문이다.
- 선택지 안의 명백한 오타는 고친다. 고친 것과 교재 오류는 노트와 최종 보고에 적는다.

### 2. 문제 풀기 (가장 중요)
- 모든 문제를 직접 풀고 정답 근거를 지문에서 확정한다. 정답이 틀리면 수업 전체가 무너진다.
- 해설서에 정답 표시가 없으면 직접 풀어서 정한다. 이렇게 정한 답은 사용자에게 확인을 요청한다.

### 3. 데이터 JSON 작성
- 필드 설명은 `references/data_schema.md`를 따른다.
- 기준 예시
  - `assets/example_unit08_summary.json`: 최신 형식의 완성본. 요약문 10 + 빈칸·삽입·어휘 변형 3, signalMap, extras, pre, reviewTest 포함. 이 파일을 기본 템플릿으로 쓴다.
  - `assets/example_suteuk03.json`: 빈칸·함의 세트. 노트 대본의 톤은 이 파일을 참고한다.
- 지문마다 `unit`(구조 하나)을 정한다. 변형 문제는 원래 지문과 같은 구조를 쓴다.

### 4. 빌드
```bash
WORK=<scratchpad>/reading-ppt && mkdir -p $WORK && cd $WORK
[ -d node_modules/pptxgenjs ] || (npm init -y >/dev/null && npm install pptxgenjs react react-dom react-icons sharp jszip docx >/dev/null)
NODE_PATH=$WORK/node_modules node <skill-dir>/scripts/build_deck.js data.json "<출력 경로>/<교재>_<단원>_수업PPT.pptx"
```
- `DEBUG_QS=1`을 붙이면 지문별 자동 글자 크기를 출력한다.

### 5. 검수
- pptx 스킬의 `scripts/office/validate.py`로 검증한다.
- soffice로 PDF → 이미지 변환해 다음을 본다.
  - 본문이 상자를 넘치지 않는지. 넘치면 그 문제에 `"qFont": 16`처럼 지정한다.
  - 형광 위치가 맞는지.
  - Signal 표가 한 줄씩 깔끔한지.
- 렌더링 환경에 맑은 고딕이 없으면 대체 글꼴이 더 넓다. 그래서 미리보기는 실제 파워포인트보다 약간 빡빡하게 보인다.
- 문법 구절은 지문에 정확히 한 번 나와야 칠해진다. 다음 명령으로 검사한다.
  ```bash
  node -e 'const D=require("./data.json");for(const e of D.exercises){const t=e.sentences.map(s=>s[0]).join(" ");for(const g of e.grammar||[])for(const p of g[0]){const c=t.split(p).length-1;if(c!==1)console.log(e.n,p,c)}}'
  ```

### 6. 전달
- 결과 파일은 **원본 교재 PPT가 있던 자리(같은 폴더)**에 저장하는 것을 기본으로 한다.
  - 원본이 구글 드라이브에 있으면 그 폴더에 업로드를 시도한다.
  - 업로드 도구로 못 올리면 그렇다고 분명히 말하고, 사용자가 옮길 수 있게 파일을 보낸다.
- 채팅에는 짧게 정리한다: 정답 목록, 교재 오류·수정, 사용자가 확인할 것(긴 지문 글자 크기, 직접 정한 정답, 슬라이드쇼에서 클릭 애니메이션).

## 내용 작성 원칙

- **노트는 선생님 공부용 + 대본.** 초보 선생님이 노트만 읽고 지문을 이해하고 설명할 수 있어야 한다.
  - 【풀이 플로우】는 "요약문 먼저 → 첫 문장 signal → … → 결론: ③"처럼 정답을 모르는 상태에서 도출하는 순서로 쓴다.
- **노란 형광은 지문당 핵심 단어·구 위주로 적게.** 많이 칠하면 강조가 사라진다.
- **문법 포인트는 지문당 4~5개.** 내신 단골 위주로 고른다: 수일치, 병렬, 관계사, 분사구문, 도치, 강조구문, 5형식 보어, 사역동사, 가정법. 설명은 "왜 이 형태인지"를 한 줄로.
- **어휘 띠는 지문당 6~8개**(각주 단어 제외). `vocabPlus`에 유의어·반의어·파생어·표현 바꿔쓰기를 넣는다.
- **글의 구조 3~4단계**: signal은 지문에 실제로 있는 표현을 짧게 그대로 따온다(… 생략 가능). 내용은 한국어 한 줄. 마지막 단계가 정답(빈칸·요약문)과 이어지게 한다. `flow`는 structure가 없을 때의 대체용.
