# David 모의고사·수능 지문분석

고등부 영어 수업용 **모의고사·수능 지문분석 책자**를 만든다. 선생님이 참고하는 exam4u 분석자료의 **구성**을 따르되, 해설 문장은 새로 쓴다.
결과물은 선생님이 **이 자료를 보고 직접 가르치는 수업용 분석 자료** Word 한 파일이다.
**문제는 만들지 않는다**: 어법 CHECK 선택형, 서술형 대비 문항, 변형문제, 시험지·답지 모두 X. 출제 포인트는 '어디서 무엇이 나올 수 있는지' 설명으로만 쓴다.
학생용 필기 노트는 선생님이 따로 요청할 때만 `--student`로 만든다. 말투는 편하게, 채팅 보고는 짧게 한다.

## 0. 절대 규칙
- **원문 지문·발문·선지는 한 글자도 바꾸지 않는다.** 평가원·교육청 원문 그대로 싣는다.
- exam4u 같은 상용 해설 자료를 받으면 **구성만 참고하고 문장은 베끼지 않는다.** 해석·구문 설명·오답 분석은 직접 새로 쓴다. (저작권: 그 자료에 무단 전재 금지 문구가 있다.)
- 정답은 직접 풀어서 확인한다. 받은 자료의 정답과 다르면 채팅에서 알리고 근거를 적는다.
- 확실하지 않은 어원(어근)은 쓰지 않는다. 억지 어원보다 빈칸('—')이 낫다. 파생어도 실제로 쓰이는 단어만 적는다.

## 1. 요청 형식과 입력
- 예: `[지문분석] 2026 9월 모평 18~24번`, `[지문분석] 고2 3월 학평 31~34번 빈칸만`, 그냥 지문 사진/HWP + "분석해줘"
- 입력 파일 읽기
  - **HWP**: `python3 scripts/hwp2txt.py 파일.hwp 출력.txt` (olefile 필요: `pip install olefile`)
  - PDF: pdf 스킬 / 사진: 직접 읽고 원문을 옮겨 적은 뒤 철자를 한 번 더 확인
- 범위(문항 번호)가 없으면 받은 자료의 모든 지문을 한다. 10지문이 넘으면 몇 번부터 할지 한 번만 묻는다.
- 출처·학년·연도를 자료에서 확인해 `meta`에 적는다. 없으면 묻지 말고 비워 둔다.

## 2. 작업 순서
1. 원문 확보 → 지문마다 문장 번호를 붙인다(1, 2, 3 …). 이 번호가 Flow Check·근거·출제포인트 전부에서 쓰인다.
2. 지문마다 3장 구성대로 분석해서 `analysis.json`을 쓴다. 형식은 `references/json-schema.md`, 완성 예시는 `assets/example-analysis.json`(2026 9월 모평 18번). 예시의 분량·설명 밀도를 기준으로 삼는다.
   - 수능 풀이 전략은 `references/suneung-types.md`에서 해당 유형 부분만 읽고 **이 지문에 맞게** 바꿔 쓴다.
3. Word 생성
   ```bash
   cd <작업폴더> && npm ls docx >/dev/null 2>&1 || npm i docx
   node <스킬경로>/scripts/build_docx.js analysis.json <출력폴더> [logo.png]   # 학생용 필기 노트도 필요하면 --student
   ```
   - 로고 파일(`David Logo.jpeg` 등)이 있으면 png로 바꿔 넘긴다. 없으면 머리글에 'DAVID' 글자가 들어간다.
4. 검수(스크립트로 확인할 수 있는 건 스크립트로)
   - 원문 = 문장들을 이어 붙인 것과 일치하는지, 문장 번호 누락 없는지
   - 정답 번호와 선지 수(5개), 근거 문장 번호가 실제 문장 번호 범위 안인지
   - 어휘 표에 빈 뜻 없음
   - docx 스킬의 validate를 돌린다
5. 채팅 보고: 만든 파일, 지문 수, 받은 자료와 정답이 다른 곳이나 확인이 필요한 곳만 짧게. 문제 세트를 만들겠냐고 먼저 묻지 않는다.

## 3. 지문 하나 분석 구성
exam4u 지문분석 순서를 따른다.

1. **머리**: 번호┃유형, 출처·학년, 영어 제목 + 한글 제목(직접 짓는다)
2. **주제문**: 영어 한 문장 + 한글. 글의 핵심을 수능 주제 선지처럼 쓴다.
3. **내용 요약** 2~3문장 + **Flow Check**: 문장 범위별 도입/전개/결론(이야기 글은 발단/전개/결말, 편지는 인사/본론/요청)
4. **원문 + 원본 문제**(발문·선지·각주)
5. **문장별 분석** (모든 문장)
   - `chunked`: 의미 단위 끊어읽기 `/`
   - `structure`: S·V·O·C, 수식어 [ ], 절 < > 표시. 복잡한 문장만.
   - `literal`: 끊은 단위 순서대로 직독직해 → `ko`: 자연스러운 해석
   - `points`: 구문 포인트 ①②… — 문법 이름 + 왜 그렇게 쓰였는지 + 바꿔 쓰기(→ =) 한 줄. 고등 내신에서 실제로 묻는 것 위주.
   - `tags`: 주제문 / 빈칸 추론 / 문장 삽입 / 서술형 대비 / 어법 / 어휘 — 출제 가능성이 높은 문장에만
6. **어휘 표**: 지문의 중요 어휘 15~25개(고3 기준, 쉬운 단어 제외). 각 단어에
   - 뜻(문맥상 뜻 먼저), 유의어 2~3, 반의어 1~2(없으면 '—'), 파생어(품사 표시), 어근·접사 풀이
   - 숙어·표현은 `idioms`로 따로
7. **수능 문제풀이**: 유형 풀이 순서(이 지문 기준) → 정답 + 근거 문장 번호 → 해설 → 오답 선지별 이유(매력적 오답 표시) → 함정 주의
8. **내신 출제포인트** (설명만, 문항은 만들지 않는다)
   - 출제 가능 유형 체크(■/□)
   - 문장별 출제 포인트와 변형 방법 표: 어법 포인트(헷갈리는 짝: that/what, 능동/수동, 동사/준동사, 수 일치 …), 어휘 포인트(반의어로 바뀔 낱말), 서술형 후보 문장(배열·영작·요약에 쓰기 좋은 문장)과 이유를 5~10줄로
9. **Grammar✚**: 지문에 나온 핵심 문법 1~3개를 표로 정리 + 예문
10. **전체 해석**

(요청 시) 학생용 필기 노트는 같은 순서에서 해석·구문 설명·어휘 뜻·정답을 비우고 필기 줄을 둔다(`--student`).

## 4. 품질 기준
- 해석은 수능 해설지 수준으로 자연스럽게. 직독직해는 끊어읽기 단위와 1:1로 맞춘다.
- 구문 설명은 짧게, 학생이 다음 지문에서도 알아볼 수 있는 규칙으로 쓴다.
- 오답 이유는 "본문에 없음"으로 끝내지 말고 **왜 끌리는지 + 왜 틀렸는지**를 쓴다.
- 풀이 전략은 일반론이 아니라 "3번 문장 However 뒤" 처럼 이 지문의 위치를 가리킨다.
- 선생님이 수업 중 바로 읽을 수 있게, 한 칸에 너무 긴 문단을 넣지 않는다.

## 5. 파일명
`{연도}_{시험}_{번호범위}_지문분석.docx` → `meta.filename`에 확장자 뺀 이름을 넣는다.
- 예: `26_9월모평_18-24번_지문분석.docx` (학생용 노트를 요청하면 `_학생용`이 붙은 파일이 하나 더 생긴다)
- 연결된 출력 폴더가 있으면 거기에 저장한다.

## 6. 디자인 (David 공통)
`scripts/build_docx.js`에 반영되어 있다. 고칠 때 기준:
- 글꼴 Malgun Gothic, 본문 10pt, A4 세로, 여백 좌우 1.8cm / 위 2.7cm / 아래 1.9cm
- 색: 잉크 #111111, 회색 #6B6B6B, 연회색 #F3F3F3, 괘선 #CFCFCF/#B5B5B5, 형광 #FFF0A0, 정답 #B3261E
- 머리글: 좌측 DAVID 로고 + 우측 회색 자료명 + 검정 하단선 / 바닥글: "Made by David" + 쪽번호(N / 총)
- 표: 검정 배경 흰 글씨 헤더, 가로선만

## 7. 후속 요청 (선생님이 먼저 요청할 때만)
- 학생용 필기 노트: `--student`로 다시 생성
- 문제·시험지가 필요하다고 하면 그때 `david-reading`(변형문제), `david-voca-5step`(어휘 시험) 규칙을 따른다.
